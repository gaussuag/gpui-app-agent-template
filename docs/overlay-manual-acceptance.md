# Overlay 人工验收

启动：在仓库根目录运行 `cargo run --locked -p desktop -- --overlay-demo`。
建议用两个普通记事本窗口作为宿主；测试结束后关闭 Demo 即可。

## 已有证据，无需重复

- 用户已确认普通预览与 Overlay 的系统剪贴板复制、删除、粘贴正常。
- 原生专项已覆盖中文输入法、Tab/Shift+Tab、Dialog/Sheet、菜单、通知。
- 已检查当前 200% 环境下的 tooltip 与滚动截图。

## 旧版使用体验确认（不代表新层级功能验收）

| 项目 | 操作 | 预期 | 用户结果 |
|---|---|---|---|
| 内容保留 | 附着记事本，在交互模式输入文字、点击计数；切 HUD 再切交互 | 同一会话内文字、计数保留；HUD 点击和滚轮作用于宿主 | 用户确认通过（2026-09-22） |

## margins 功能（用户已确认正常）

启动最新构建的 `target/x86_64-pc-windows-msvc/debug/gpui-app-agent-template.exe --overlay-demo`。
在 Demo 输入上/右/下/左边距，先试 `48 / 8 / 8 / 8`，点击“应用边距”，
再返回文件浏览器或无边框宿主：在留白标题区拖动、留白边缘拉伸；
根据宿主实际标题栏高度调整。HUD 和交互模式都应保留宿主操作。
切换 DPI 后留白随缩放变化；四边恢复为 0 可恢复完整客户区覆盖。
配置单位为逻辑像素，留白既不显示 Overlay 也不拦截输入。
普通窗口预览不应用边距。过大边距会暂时隐藏 Overlay，调小后内容保留并恢复。
这些是新增功能的人工验收，不要求重做此前清单或统一回归。


## 新层级跟随：本轮待验收

启动本轮构建：

```powershell
.\target\x86_64-pc-windows-msvc\debug\gpui-app-agent-template.exe --overlay-demo
```

不用重做上述旧项目。选一个普通窗口作为宿主，再准备一个其他应用窗口：

| 操作 | 预期 | 状态 |
|---|---|---|
| 附着后切其他应用，让它盖住宿主右半边 | Overlay 失焦仍显示；被挡住的部分随宿主一起遮挡，不盖在其他应用上 | 待人工 |
| 交互模式点击左侧露出的计数按钮，再输入文字 | 首击只加 1；宿主和 Overlay 一起前置；文字输入仍在 Overlay | 待人工/解锁后自动化 |
| 从任务栏切回宿主，拖标题栏、拉边框；自绘标题栏用现有 margins | 不需要第二次点击启动拖动；宿主操作自由响应 | 待人工 |
| 宿主弹出使主窗口禁用的模态对话框，然后关闭 | 对话框在 Overlay 上面；Overlay 输入暂停，关闭后恢复，文字与计数保留 | 待人工 |
| 最小化/还原，Win+D、切换虚拟桌面 | 不留下孤立 Overlay，不主动抢回前台；恢复后跟随 | 待人工 |
| 普通/置顶宿主切换，与其他置顶窗口重叠 | 同一分组、正确遮挡，不永久全局置顶 | 待人工 |
| 中文 IME / 原生子控件 / 宿主忙碌后恢复 | 不吞首击或输入；无法确认前置时显示提示，无重复请求 | 待人工；真实 WebView 集成仍是后续范围 |

若出现“Host promotion completion is unknown”提示，代表已提交的请求尚未得到可靠确认。
它可能迟到生效；当前会话继续跟随，但不再追加宿主前置请求。解除附着后重新附着可恢复请求能力。
模式切换不会替代重新附着。不要通过反复点击测试去堆积宿主请求。

自动化入口：`.\scripts\smoke-overlay.ps1 -Suite presentation`。仅在解锁桌面运行；
本轮已遇到前台资格失败而中止，没有把它计为通过。
新行为的 60Hz 延迟/CPU、1/4 会话性能、独立窗口过渡帧仍待测量；此前人工 60Hz 接受不沿用为本轮定量结果。


Demo 的“刷新诊断（只读）”显示累计协调采样、层级/位置写入、前置请求和最长协调耗时。
可在静止 60 秒前后各读取一次，确认采样增加而层级/位置写入与前置请求不持续增加。
这不等同于完整性能验收。代码调用方可读取 `snapshot.presentation.recent()`，最多 32 条、按时间顺序；
包含原生前台/捕获/邻居句柄、操作计数和结果。CPU 数据来自 Windows 线程记账，短采样可能为零，
查询失败为 None，不能将其解释为精确的亚毫秒 CPU 测量。
